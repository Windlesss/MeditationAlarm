## 16:5x 方案 B（GCD 调度链）+ 屏幕常亮 + 静音守护（用户「开始行动」后实施）

**根因回顾**：间隔音挂主 RunLoop Timer，真机实测后台锁定态被系统节流（完全不触发）；背景音由音频会话驱动所以全场景正常。用户否决通知方案，要求全场景走音频。

**已实施**：
1. **方案 B**：`SessionController.chimeTimer`（主 RunLoop Timer）→ 私有队列 `DispatchSourceTimer`（qos .userInitiated，leeway 100ms）。「下一次事件」= min(下一间隔提示, 结束时刻) 一次排一个，到点自愈重排；handler 里 `Task { @MainActor }` hop 回主线程播放（主队列是 run-loop source 非 timer，锁屏照常处理）。前后台同一条链，废除互斥切换，双响隐患结构性消失。
2. **结束音**：`end(reason:)` 去掉 isInBackground 分支——自然到头（前台/后台/锁屏）一律三声渐强，手动结束单声。
3. **静音守护**：`Resources/Audio/keepalive-silence.wav`（Python wave 生成 1s 单声道静音，88KB，已入包）；`AudioEngine.beginSilentKeepAlive/stopSilentKeepAlive`——无背景音会话退后台时循环播放数字静音（volume 0）守住音频会话，保证 App 不被挂起、调度链不停摆。
4. **屏幕常亮**：`syncIdleTimer()`，不变量 `isIdleTimerDisabled == (phase == .running)`，挂在 start/pause/resume/end/reset/enterForeground/enterBackground；无开关（用户决策：始终常亮不可调，仅运行态生效，暂停即恢复）。
5. **顺手修复**：结束音播完以前背景音无限循环没人停（deactivateIfIdle 看到 ambient 在播就跳过释放，而无任何地方停 ambient）——新增 `windDownSession`：尾声后淡出停 ambient + 停守护 + 释放会话，带 isInSession 双重守卫防与新会话竞争。`endSessionQuietly` 死代码已删。
6. **通知停用**：`ensureAuthorization`/`armAll` 调用移除，只在状态切换 disarm 清残留；ReminderScheduler 与 chimes-caf 保留不用（用户决策）。

**验证**：BUILD SUCCEEDED；swift test 40 全绿；模拟器 `-selfTest`（35s/12s/rain）日志确认 2 次间隔音 + 结束三声渐强（0.36/0.576/0.8）全由调度链触发。**锁屏/后台真机验证待用户**（模拟器无法复现锁屏）。

**教训**：Write 整文件重写时把 `startUITimer` 的 `repeats` 误写成 false，已发现并修正——重写大文件后必须对照原文 diff 关键参数。

**待用户真机验证清单**：① 前台回归（提示音准点/结束三声/灵动岛）；② 后台未锁（响、无通知）；③ 锁屏跨 ≥2 个间隔都响；④ 锁屏自然到头三声渐强+灵动岛消失；⑤ 无背景音+锁屏（静音守护路径）；⑥ 暂停/继续后再锁屏；⑦ 系统自动锁屏设 30s 验证常亮：运行中不灭、暂停恢复倒计时。
