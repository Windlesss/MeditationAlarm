## 踩坑记录（重要）
1. **SwiftData `delete + save` 在本环境稳定失效**：save 静默失败、记录原样留库（实测两次）。根因未明（疑似带 @Relationship 模型的 delete 事务问题）。**解法：作废标记 `isDiscarded` 代替 delete**——finish 短分支把记录闭合 + 标 discarded，用户选「记录」时把同一条写活。防御：begin() 开新会话前闭合残留 open 记录
2. **偶发双 start**（install/launch 竞态，4 轮复现 2 轮）：第二次 start 的调用方始终没抓到（栈日志只看到 selfTest 一次）。已三重防护兜底：begin 闭合残留 + restore 跳过空壳 + @Query 过滤
3. **模拟器设备 udid 会变**：booted 从 E584ABD7 变成 42642175，查 sqlite 库前必须 `simctl get_app_container booted` 重新定位；SwiftData store 实际落在 **App Group 容器**（`Shared/AppGroup/*/Library/Application Support/default.store`），不在 App 沙箱
4. **launch 前 App 没 terminate 干净会导致数据叠态**（查询结果混乱的来源）——验证数据库前先 terminate + sleep 1
5. sqlite 时间戳换算：CoreData 时间 + 978307200 = Unix
