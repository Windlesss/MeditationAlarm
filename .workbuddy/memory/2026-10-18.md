### 踩过的坑（重要，别重复踩）
1. **Swift 版本报"Swift 3.x"**：`project.yml` 没写 `SWIFT_VERSION` → pbxproj 里 0 处 SWIFT_VERSION → Xcode 判定为 Swift 3 遗留工程。修复：两个 target 都加 `SWIFT_VERSION: "5.0"`。
2. **语言版本选 5.0 而非 6.0**（用户拍板）：Swift 6 的价值是编译期并发检查，等主流程跑通再切。已知切 6 时会撞：`SessionController.deinit` 隔离、`DarwinListener` 的 C 回调裸指针。
3. **XcodeGen 2.46 不再默认写 `PRODUCT_NAME`**：产物变成 `Debug-iphonesimulator/.app`（空名），报 "Multiple commands produce .app"。必须显式写 `PRODUCT_NAME`。
4. **XcodeGen 的 `type: folder` 会把引用路径改写成 basename**：`path: Resources/Audio` 生成的 fileRef 是 `path = Audio`，与磁盘不符，报 `lstat(.../Audio): No such file or directory`。改用 `type: resources` 平铺入包（chimes/ambient 文件名不重复）。
5. **放弃 SwiftPM 包依赖**：Xcode 包解析必写 `~/.swiftpm/security`，沙箱与提权都拦。改为把 `Packages/MeditationCore/Sources/MeditationCore` 直接编入两个 target（好处：两侧永远同一份代码）。`swift test` 仍走独立包。
6. **`CFNotificationCenterAddObserver` 是 6 参**：`(center, observer, callback, name, object, suspensionBehavior)`，第 5 个必须给 `nil`；没有独立的 coalesce 参数（`CFNotificationSuspensionBehavior` 里才有 `.coalesce`）。
7. **`@MainActor` 类的 `deinit` 访问隔离属性是硬错误**（Swift 5 模式也拦）。`nonisolated` 不能用于可变存储属性（@Observable 宏会将其变成 tracked），唯一解是 `nonisolated(unsafe)`，会留一条无害警告。
8. xcodebuild 必须加 `-derivedDataPath ./Build/DerivedData` 且整体提权运行，否则沙箱拦 DerivedData。

## 第二轮：音频 + 实时活动接线，模拟器全链路验证通过

### 用户本轮反馈的三个问题（全部解决）
1. 选提示音/背景音、调音量时要试听播放 → 已实现（含音量条 80ms 防抖）
2. **间隔音和背景音都没真正播放** → 根因：AudioEngine 整个不存在，一行播放代码都没有
3. **App 没有上实时活动** → 根因：Widget 侧画好了视图，但 App 侧从未调用 `Activity.request`

### 新增文件
- `MeditationAlarmApp/Audio/AudioEngine.swift` —— @MainActor 单例。AVAudioPlayer（不用 AVAudioEngine）；试听与会话两套状态；ducking 用 token 管理；结束音三声渐强由引擎自行延后释放会话（`setActive(false)` 会掐掉尾声）
- `MeditationAlarmApp/LiveActivity/LiveActivityController.swift` —— request/update/end + self-healing
- `MeditationAlarmApp/Notifications/ReminderScheduler.swift` —— 方案 C 的通知兜底，滚动排程（只排下一发+结束，避开 iOS 64 个待投递上限）
- `Shared/DebugLog.swift` —— `dbgLog()`，`#if DEBUG` + `@autoclosure`，release 零开销

### 接线方式
SessionController 直接调 `AudioEngine.shared` / `LiveActivityController.shared`（进程级单例，不注入），scenePhase 管通知兜底开关 + 上岛自愈，AppDelegate 转音频中断。App 层必须持有 `DarwinListener`（Unmanaged 裸指针自持，不留就会被释放 → 岛上按钮失效）。

### 新踩的坑（重要）
1. **XcodeGen 不写 `SWIFT_ACTIVE_COMPILATION_CONDITIONS`** → `#if DEBUG` 永远不成立，自测钩子静默失效，且无任何报错。必须显式声明。
2. **XcodeGen 的 target 级 `settings.configs` 会整个取代该 configuration 的设置**，把 `SWIFT_VERSION` / `PRODUCT_NAME` 一起冲掉（报 `SWIFT_VERSION '' is unsupported`）。正确做法：`configs` 放 **project 级**，靠 Xcode 的 target-over-project 层级合并。
3. **`Activity.request` 是同步 `throws`，不是 async**；`ActivityAuthorizationInfo.areActivitiesEnabled` 是普通属性。误加 `await` 会报 "no 'async' operations occur within 'await'"（warning）。所以上岛可以完全同步，无 task hop。
4. **`Activity.update` / `Activity.end` 才是 async**。
5. **新建文件后必须重跑 `xcodegen generate`**，否则报 "cannot find 'X' in scope"。
6. **`print` 到管道是块缓冲**，`log show` 抓不到；要用 NSLog（或 dbgLog）。
7. **`xcodebuild build` 默认 Release configuration**，要用 `-configuration Debug` 才走 DEBUG 分支。
8. **模拟器里 App 全屏前台时，灵动岛只显示纯黑药丸**；要把 App 推后台（如启动 Preferences）才能看到 Live Activity 的 compact 视图。
9. **后台音频验证方法**：`log show` 里 grep `runningboardd.*MeditationAlarm`，出现 `MediaPlayback` + `AudioRecording` 电源断言即证明音频会话已激活、App 拿到后台播放能力。

## 第三轮：真机反馈三个问题的根因分析（只分析，未改代码）

用户真机反馈：① 开始计时后背景音不播；② 退后台后间隔音不按点播；③ 中途退出后 App 连响三次「间隔音」。（setup 试听、实时活动、前台间隔音均正常）

根因（代码级定位）：
1. **SetupView.onDisappear → AudioEngine.quietDown() → stopAllPlayers()** 把 beginSession 刚起播的背景音杀掉。quietDown 本意是清理试听，`deactivateIfIdle()` 有 `isInSession` 守卫但 `stopAllPlayers()` 没有。视图切换与 start() 紧邻发生，背景音起播后数毫秒即停。模拟器自测未暴露：日志只记起播瞬间。
2. 后台两条路径全断：a) chimeTimer 挂主 RunLoop，App 挂起即停摆——问题 1 导致后台无音频输出，系统会挂起 App；即使活着，后台 Timer 也会被合并延迟。b) 本地通知**从未调用 requestAuthorization**（全工程 grep 只有 add/remove），通知永不投递；且滚动重排依赖 fireInterval，挂起后无人重排。隐患：权限修好且 App 活着时 Timer 与通知会双响，两条路径无互斥。
3. 「三次间隔音」= `playEndingChime` 三声渐强（0.45/0.72/1.0，间隔 1.6s），且 `endChimeID = chimeID` 与间隔音同文件；触发时机为会话在用户退出后到点（App 活着→后台到点播；挂起→重开瞬间首个 tick 补播）。

修复方向（待用户确认后实施）：stopAllPlayers/quietDown 加 isInSession 守卫；申请通知权限；前台 Timer / 后台通知互斥；通知音需把 chime 转 caf/wav（UNNotificationSound 不支持 m4a）；后台排程改一次排完全部剩余间隔（64 上限）；结束音后台策略待定。

### 用户确认 + 问题 1 已修复
- 用户确认：①「三声」= 点开始后**主动点结束**触发，即 Q6 结束音三声渐强（与间隔音同文件，听感无区分）；② 各种背景音都测过，起播一瞬间即被杀（与 onDisappear 根因完全吻合）；③ 后台完全没声（两条路径俱断）。
- **问题 1 已修**：`AudioEngine.quietDown()` 加 `guard !isInSession` + dbgLog。`xcodebuild -configuration Debug -sdk iphonesimulator` **BUILD SUCCEEDED**。
- 问题 2 方案（已定，未实施）：前台 chimeTimer / 后台本地通知互斥。退后台撤 Timer、一次排完全部剩余间隔（≤64）+ 结束通知；回前台撤通知恢复 Timer。后台结束只由通知发声（三声渐强无法通过通知实现）。待用户决策：通知音色（转 caf vs 系统默认）、结束音行为（手动结束单声 vs 三声渐强 vs 换音色）。
- 已知平台限制（实施时需告知用户）：本地通知声音受静音开关控制；App 存活时通知音不触发 ducking。

### 三个问题全部修复（用户确认决策后实施）
- **问题 1（背景音被误杀）**：`AudioEngine.quietDown()` 加 `guard !isInSession`。
- **问题 2（后台不响）**：前后台**互斥**重构 —— 前台 chimeTimer（`scheduleNextChime` 加 `!isInBackground` 守卫）；退后台 `enterBackground()` 撤 Timer + `armAllReminders()` 一次排完全部剩余间隔（新增 `IntervalSchedule.remainingReminders` 纯函数 + 5 个单测，共 40 测试全绿）+ 结束通知；回前台 `enterForeground()` 撤通知恢复 Timer；首次 start 时 `ensureAuthorization()` 申请权限。
- **问题 3（结束连响三次）**：用户决策「手动结束单声、自然结束三声渐强」→ `end(reason:)` 分流；新增 `AudioEngine.EndingStyle`（crescendo/single）与 `endSessionQuietly()`（后台静默收场，声音由结束通知出）。
- **通知音**：8 个提示音 m4a → `Resources/Audio/chimes-caf/*.caf`（afconvert -f caff -d ima4，各 ~140KB，已入包）；`ReminderScheduler` 重写为 armAll/disarm/ensureAuthorization，`UNNotificationSound(named:)` + `interruptionLevel = .timeSensitive`，64 枚上限截断。
- 同步更新 REQUIREMENTS.md 的 Q1/Q6 行。`xcodebuild Debug` + `swift test`（40 个）全绿。
- **待真机验证**：① 起播后背景音不再被杀；② 退后台按点响 caf 提示音、不双响；③ 前台手动结束单声、自然结束三声渐强；④ 首次开始的权限弹窗。
