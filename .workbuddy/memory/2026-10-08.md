# 2026-10-08

## 冥想闹钟 iOS App — 需求梳理与确认

产出 `REQUIREMENTS.md`（v1.0，核心需求已确认）。环境：Xcode 26.0.1 / macOS 26.5.1。

### 已确认的技术决策
- **后台/息屏打铃 = 混合方案**：`UIBackgroundModes: audio` + AVAudioSession 后台常驻为主（保证音质、混音、ducking），同时排程 `UNNotification` 本地通知兜底（App 被杀仍响）。需要做"两套都响"的去重：用已播放时间点集合判重。
- **最低 iOS 17.0**（灵动岛硬件门槛是 iPhone 14 Pro+，无灵动岛机型走锁屏 Live Activity）
- **v1 只做核心**：设置页 + 计时页 + 灵动岛/锁屏 + 提示音 + 背景音。统计/历史（SwiftData）列入 v1.1。
- **计时真相源 = 绝对时间戳**（`startDate` + `accumulated`），绝不用 Timer 累加。持久化到 App Group UserDefaults，冷启动可恢复。灵动岛用 `Text(endDate, style: .timer)` 由系统自动倒数，不消耗 Live Activity 更新预算。

### 待定 / 默认实现
- 音频素材方案未定（内置采样 vs AVAudioEngine 程序化合成 vs 混合）。开发策略：抽象 `SoundSource` 协议，后续替换实现不动业务代码。
- 默认实现（用户可改）：联动规则只在「总时长 < 间隔」时拉到 5 倍，[间隔, 间隔×5) 区间保持用户输入；结束音默认三声渐强；开始前 3 秒预备倒计时；ducking 默认开启；Live Activity 8 小时上限 v1 不处理。

### 术语澄清（用户提出疑问后补充）
用户对"灵动岛 vs 实时活动"关系不清楚，已在 REQUIREMENTS.md 新增 D0 章节澄清：
- **Live Activity（实时活动）= 软件能力**（ActivityKit，iOS 16.1+，全机型）；**灵动岛 = 硬件挖孔 + 展示容器**（iPhone 14 Pro+）。二者是"内容 vs 容器"关系，不是并列功能。
- Live Activity 只显示不运行：UI 跑在 Widget Extension 进程，主 App 仍会被挂起。**"后台不中断"不由 Live Activity 保证**，靠绝对时间戳 + 后台音频会话。
- 需编写的视图变体：`lockScreen`（全机型，必做，优先级最高）、灵动岛 `expanded`/`compactLeading`/`compactTrailing`/`minimal`、AOD 复用锁屏视图。
- 文档措辞已统一：FR-6 标题改为"实时活动（Live Activity）"，灵动岛降为子项。

### 导航结构（用户第四轮）
记录入口放**主界面右上角图标**，不做底部 TabBar。理由：TabBar 把视觉重心一分为二、挤压计时区留白，且记录功能当前为空做主 Tab 落差大。预留期落地页显示"记录功能即将推出"+ 极简线条插画（不用 emoji）。图标用 SF Symbol `chart.line.uptrend.xyaxis`，Ultralight 20pt，三级色。

### HealthKit 集成（用户第四轮提问）
- **正念分钟数 v1 做**：`HKCategoryType(.mindfulSession)`，value 必须 `HKCategoryValue.notApplicable.rawValue`(=0)。HealthKit 无最短时长限制，"超 1 分钟才同步"是产品逻辑。
  - **关键**：暂停要按运行区间分段写（`segments: [(start,end)]`），否则 20 分钟冥想 + 5 分钟暂停会虚报 25 分钟。App 被杀时回前台补写。
  - 需 `NSHealthUpdateUsageDescription` + HealthKit Capability；iPad 用 `isHealthDataAvailable()` 降级。
- **HRV 有限制（已告知用户）**：Apple Watch 的 HRV 由系统间歇自动采样，**App 无法主动触发测量**。"开始前/结束后取一次"实为取时间窗内最近可用样本，前后对比可信度有限。
  - 类型 `HKQuantityTypeIdentifier.heartRateVariabilitySDNN`，单位是时间（ms）。
  - **更可靠的主指标是心率**：采样密集，取前后窗口均值对比。HRV 取不到显示「—」不要显示 0。
  - 真正连续监测需自研 watchOS App + `HKWorkoutSession`（v2 评估）。
  - 审核：需隐私政策，读取权限比写入权限审核更严。

### 提示音 V2（用户反馈初版太长）
用户要求 2–3s。已重做，8 条全部 2.4–3.0s，总 740KB（原 2.0MB），峰值统一 -1dBFS。
- **重要发现**：Commons 部分录音是「摩擦演奏」非单次敲击，能量峰值不在起始处（rin-strike 在 3.4s、rin-friction 在 12.6s、bowl-small 在 41.3s）。用 `silencedetect` 找起音会剪到几乎无声的开头。改为**解码 PCM 后滑动窗口找能量峰值**来定位裁剪起点。
- 处理链：能量峰值定位 → atrim → `afftdn=nf=-30:nr=8` 轻降噪 → `afade=t=out:st=0.1:curve=exp` 指数衰减 → 峰值归一（增益封顶 +18dB 防噪声放大）→ AAC 192k
- ffmpeg 踩坑：`-v error` 会吞掉 `volumedetect` 输出（它是 info 级），测量音量必须用 `-hide_banner` 不加 `-v error`

### 后续决策（用户第二轮确认）
- **Live Activity 8 小时超时：不处理、不提示**。采用 self-healing：App 每次进前台检查 `Activity.activities`，若计时仍在跑但 Activity 不存在则重建。注意 `activity.update()` 不重置 8 小时计时，必须 `end()` + 重新 `request()` 才重置。顺带修复"用户杀 App 后 Activity 消失"。
- **用户导入本地音频**：技术可行，难度 ★★☆☆☆，排入 v1.1。坑：security-scoped URL 须 copy 进沙盒、DRM 文件会失败、ogg/flac 不支持、iCloud 未下载文件需异步、需提供删除入口。不需要放 App Group（播放只在主 App）。

### 心率/HRV 连续采样（用户第五轮，方案定型）
用户要求：会话内每 10/30s 采样并存库，结束时画曲线；全零则自动隐藏；不纠结 HRV 采样频率，系统给什么存什么。
- **定性**：iOS 端是**读取** watchOS 已写入的样本，第三方无法命令手表"立刻测一次"。所以"每 30s 采样"= 每 30s 去数据库捞新样本。
- **采集三层**：① `HKAnchoredObjectQuery`（带 updateHandler，会话开始建立并保持，新样本即时回调）② `HKObserverQuery` + `enableBackgroundDelivery`（App 未运行时被唤醒补录）③ 每 30s `HKSampleQuery` 兜底 reconcile（10/30/60 可配，默认 30）
- **去重是命门**：不去重的话一条 HRV 会被反复拉取 20 次，画成虚假平线。去重键 = `HKObject.uuid`，兜底 `(startDate,endDate,value)`
- **渲染诚实原则**：心率 ≥2 点用 LineMark 平滑连线 + PointMark；**HRV ≥2 点只画 PointMark + RuleMark 竖线，绝不连线**（稀疏点连线=编造趋势）；1 个点显示单值不画图；0 点或全零则**整块不渲染（含标题）**
- HealthKit **读授权状态无法查询**（拒绝与"有权限无数据"都返回空），所以自动隐藏规则天然覆盖授权被拒，无需额外分支
- 单位：`heartRate`=bpm，`heartRateVariabilitySDNN`=ms。X 轴统一用相对冥想起点的分钟数
- **预期要管好**：静息时手表 HR 约 5–10 分钟一条，HRV 更少且多在睡眠期。20 分钟冥想大概率只有 2–4 条 HR、0–2 条 HRV，HRV 区块会经常自动隐藏——这是预期行为
- 真正每秒级监测需 watchOS target + `HKWorkoutSession(.mindAndBody)` + WatchConnectivity → **v2 评估**
- v1 因此引入 **SwiftData**（`MeditationSession` / `VitalSample`），但**记录查看页仍属 v1.1**

### 关键风险
- Live Activity 最长活跃约 8 小时，永久运行模式超时后灵动岛/锁屏显示会消失（App 内计时与打铃不受影响）。
- 第 3、4 步（Live Activity、后台音频）必须真机验证，模拟器测不了。
- 第 7–9 步（HealthKit）需**配对 Apple Watch 的真机**才有真实样本；无手表只能验证"空→隐藏"路径。
- CC BY / CC BY-SA 素材有署名义务，上架前必须做署名页。
